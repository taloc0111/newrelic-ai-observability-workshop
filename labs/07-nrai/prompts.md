# Lab 4 - New Relic AI (generative AI) - prompt sheet

**Where:** the **Ask AI** button, top right of most New Relic pages (also inside the Query builder, the Issue page, Errors inbox and Logs). New Relic AI is GA since 4 Jun 2025 and **consumes Advanced Compute units**: on an account without the Advanced Compute add-on the button is missing or disabled. If that is your account, run the NRQL in `nrql-cheatsheet.md` by hand and keep the talking points; the lab still works, only the "English in" part is missing.

Every prompt below follows the same loop: ask, **open the generated NRQL before you trust the number**, compare with a screen you already know (Lab 3 Issue page, APM Summary), then ask a follow-up.

| # | Say this (Ask AI) | Expect | Then |
|---|---|---|---|
| 1 | `Show error logs from the Kubernetes namespace simplcommerce in the last hour` | NRQL on `Log` with `namespace_name = 'simplcommerce'` and a level filter (`level = 'ERROR'`), chart or table; a "Run query" / "Open in query builder" link | Open the query. **Rehearsal 2026-11-07:** it wrote `WHERE namespace = 'simplcommerce' AND message LIKE '%error%'` and showed **"No logs found"** - the attribute is `namespace_name`, and with that one word fixed the same query returns 318 lines. It also tells you which event types it considered (`Log, K8sNamespaceSample, K8sPodSample`). Check attribute names against the Logs UI before believing an empty result |
| 2 | `count them per 5 minutes as a chart` (same conversation) | Chat is **stateful**: it should rewrite prompt 1 with `TIMESERIES 5 minutes`. If it starts a new query on `Transaction` or `K8sPodSample`, the context was lost | **Rehearsal:** context kept and the attribute silently corrected to `namespace_name`, but the filter became `error.class IS NOT NULL` - an APM attribute that Fluent Bit log lines never carry - so the chart is a **flat line at 0** that looks like "no errors". A plausible chart of a wrong query. Replace the filter with `level = 'ERROR' OR message LIKE '%fail:%'` (cheat sheet 2) and the bursts appear |
| 3 | `Which transactions of SimplCommerce had the highest error rate in the last 2 hours?` | `SELECT percentage(count(*), WHERE error IS true) FROM Transaction WHERE appName = 'SimplCommerce' FACET name SINCE 2 hours ago` (approx.) | **Rehearsal:** it queried **`TransactionError`** with `percentage(count(*), WHERE error IS true) FACET transactionName` and answered **`WebTransaction/StatusCode/500` = 0 %** - a table that reads as "no errors" two hours after a 15-minute outage. `TransactionError` rows have no `error` attribute, so the percentage is 0 by construction. Run cheat sheet 3 on `Transaction` next to it: `/api/demo/throw` at 100 %, the rest at 0 |
| 4 | `Show open issues and which condition opened each` | A list from the Issues page (NRAI calls the issues tool) or NRQL on `NrAiIncident` / `NrAiIssue` | **Rehearsal:** `FROM NrAiIncident SELECT count(*) FACET conditionName WHERE event = 'open' SINCE 1 hour ago` -> "error rate 3, log spike 2, lab5-test 1". That is a count of alert-event **openings in the last hour**, not of open issues: at that moment **zero** issues were open. Same words, different question. Open **Alerts -> Issues & activity** next to it |
| 5a | `What is wrong with SimplCommerce right now?` (vague on purpose) | Either a guess (host CPU, a Kubernetes query) or, on an account with Response Intelligence, a summary that pulls the open issue, affected entities and recent deployments | **Rehearsal:** `SELECT latest(error.message), latest(error.class) FROM TransactionError ...` -> "Demo 500 - injected unhandled exception / System.InvalidOperationException". A fair answer (it considered `TransactionError, NrAiIncident, Log`), but "latest error" is not "what is wrong": it would say the same on a healthy day. Name the entity type and the signal: `open issues on the APM application SimplCommerce` |
| 5 | `How many requests per minute did SimplCommerce serve today?` | `SELECT rate(count(*), 1 minute) FROM Transaction WHERE appName = 'SimplCommerce' TIMESERIES SINCE today` | **Rehearsal: correct**, and the chart carries the **Changes** toggle: the two `v1-rollback` deployment markers from Lab 3 sit exactly where the traffic came back. This is the series Lab 6 predicts |
| 6 | `Write an NRQL alert condition that fires when SimplCommerce error rate is above 5 percent for one minute` | The NRQL plus a threshold suggestion; some versions offer "Create alert condition" | **Rehearsal:** no NRQL at all - NRAI called its **alert recommendations** tool and offered three ready conditions for the APM entity (Response time, Throughput, Error rate) with an **Add alerts** button. Press it on a scratch policy and open the result: compare with `labs/04-alerts/condition-error-rate-static.graphql` (threshold, window, aggregation method, loss of signal) - the script is the reviewed version of this answer |

**Explain this error:** two entry points. (a) **Triage Inbox (Errors inbox)** or APM -> SimplCommerce -> Errors: open the `/api/demo/throw` group, **Stack trace** panel, **Explain this error**. (b) **APM -> SimplCommerce -> Logs**: click an `ERROR` line (`newrelic.source = logs.APM`, with `trace.id` and `span.id`), the **Explain this error** button on the log details panel. Rehearsal (b): a correct one-paragraph reading ("a demo fault intentionally triggered... likely a test") followed by five generic next steps (review code, logging, tests, configuration, documentation) with links to Microsoft and New Relic docs. Useful as a first read of an unfamiliar stack trace; generic beyond that. Ask `how do I reproduce it locally?` as a follow-up. The text comes from the message and stack trace, not from the Kubernetes events.

**Response Intelligence (Issue page, preview):** open the Lab 3 issue (the one with 3 alert events). Rehearsal on the course account: an **AI summary** block with three panels. **What's impacted**: "CRITICAL issues due to an error rate exceeding 5% ... linked to the kubernetes environment ... associated with error log spikes in the simplcommerce namespace ... post-alert mean 0.1 compared to a baseline mean of 0.03" - it read all three alert events and the entity tags, and it quotes real numbers. **What happened previously**: "We couldn't find a relevant retrospective document" until you link retrospectives (Knowledge). **What to check** (1 of 4-5 cards): on the Lab 3 issue the first card was **"Deployment event: Rollback Deployment - revert the current version (v1-rollback) of SimplCommerce to the previous stable version"**. That deployment marker is the *fix* we recorded after `mssql-up`; the model saw "deployment near the issue" and inferred cause from proximity. On the Lab 5 issue the card was "Database operation: investigate long-running transactions on catalog_category, shoppingcart_cartitem..." - real table names from the traces, generic advice. Neither card says "the SQL Server pod was scaled to 0": no agent in that pod, no signal (same blind spot as Dynatrace Davis). A **Potential causes** tab sits next to Overview.

**Query builder:** NRQL console, the **Ask AI** toggle next to the query box turns English into NRQL in place and the **Explain** action turns NRQL into English (paste `labs/08-log-condition/condition.nrql`; it should read the comments too, so comment your conditions).

**Talking points**
- NRAI answers from **your** account data with **your** permissions; prompts are not used to train the model; not available on HIPAA/FedRAMP accounts.
- A wrong query can return a plausible answer: compare with the Issues page or APM Summary before quoting a number. In the rehearsal, 3 of 3 generated queries were wrong (wrong attribute, wrong filter, wrong event type) and 2 of them produced a confident "no errors" picture right after an outage. The value is the draft and the list of event types it considered; the review is yours.
- Cost: each Ask AI answer is an Advanced Compute action. **Administration -> Consumption Management -> Advanced Compute Bundle** (toggle "Non-billable consumption" on a trial account) shows what it cost. Rehearsal 2026-11-07: about 7 prompts, 1 Explain this error and 2 issue-page AI summaries added up to **1.27 CCU** under "New Relic AI" - roughly 0.1 CCU per action, about $0.06 at the $0.60 list price. The NRQL `NrMTDConsumption` raw numbers are not in CCU; trust the page. Free fallback: the cheat sheet.
